# V4.1 Requirement

Run DeepSeek V4.1 GGUFs as an ordinary engine family through the shared run, serve, info, and benchmark paths. Derive geometry from metadata and tensor relationships, supporting base and pruned expert counts without artifact, revision, shape-membership, or device-name whitelists. Use the PR 28696 `deepseek41` convention and standard GGML tensor types, initially Q8_0 Engram with bounded disk reads; accept known metadata aliases and name unsupported encodings explicitly. Keep conversion outside the engine as an explicit, one-time artifact operation, never a runtime cache or safetensors execution path. Local memory fit determines whether to run an artifact, not whether to support its architecture. Reuse shared kernels and serving infrastructure, use the existing HF oracle for the first conversion-plus-execution signal, then an independently decoded GGUF oracle for execution-only checks; pursue exact batched prefill and prefix reuse separately from approximate methods. Historical research is [archived](archive/DEEPSEEK-V41-STRATEGY-2026-10-18.md); current operation and verification belong in [the bring-up notes](DEEPSEEK-V41-BRINGUP.md).
