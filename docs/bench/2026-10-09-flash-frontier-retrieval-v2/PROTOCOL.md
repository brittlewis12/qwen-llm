# Flash frontier retrieval v2 — pre-acquisition protocol

This is a separately versioned, retrieval-only follow-up motivated by v1 GSQ
format noncompliance: both arms returned the expected fields without the
required FINAL_JSON marker. V1 remains INCONCLUSIVE for GSQ and PASS for UD
forever under its own policy. V2 is not an independent replication, does not
reclassify v1, and does not rerun its separately valid technical-text NLL screen.
An owner must assess these distinct bodies of evidence together. There is no
automatic promotion or combined-v1-PASS verdict.

## Fixed inputs, before GPU acquisition

Exactly two new registry cases, in order v2_before then v2_after. Requested
record/code pairs are P-28 / amber-lantern-6149 and W-57 / jade-harbor-2856.
Authoritative facts lie respectively before and after frontier 2051, near
positions 1024 and 3072. Each includes a superseded draft code
obsolete-elm-1935, unrelated maintenance entries, and wrong-record Z-99 with
the distinct wrong code umber-ridge-4072. Each correct code occurs exactly once
in rendered prompt text, solely in the authoritative fact; freeze/check and
runtime validation enforce this. These values are specified independently of
model output, but the output contract is deliberately informed by v1.

Use the actual released UD and GSQ GGUF no-thinking templates, with the complete
question and generation suffix intact. Both templates must render identical
text and both tokenizers must yield the same 4096 IDs. Only irrelevant synthetic
filler counts and a final filler line are CPU-sized. No prompt truncation,
source-window search, answer duplication, or GPU/model-output-based sizing.
Retain messages, rendered text, templates, tokenizer identity, full IDs and
fact token spans. Producer, protocol, independent analyzer and v1 provenance
files are bound by the manifest written last. Freeze refuses an existing
manifest. Check uses CPU metadata and native qwen-tok, never model tensors.

Both artifacts receive these same frozen inputs. Acquire each artifact once;
preserve every attempted trajectory. No output-informed retry, fixture
replacement, contract relaxation or token-budget extension after acquisition.
Any later experiment needs a separate version; these results remain unchanged.

## Arms and acquisition

A: current production arithmetic/router, schedule 2048+3+2045.
B: the existing test-only schedule override, 2048+2048, same production arithmetic.
Fresh 4096 prefill for every arm; v2_before order AB, v2_after order BA.
One normally leased/admitted artifact and native runner per process, capacity
4160 and packed capacity 2048. Reuse normal selected scratch and memory gates;
the existing diagnostic gate conservatively prices a checkpoint plus 96 MiB,
although no checkpoint or full-logit history is allocated. Reset and zero
persistent storage outside each ordinary call. No observers, census or timing
claim; preserve causal position/QSA/PLE metadata, source and artifact bindings.

Generate greedy lowest-token-ID ties, at most 64 tokens. Check all full-vocabulary
logits finite at each choice and the terminal row finite. Stop on released EOS
248046 without decoding or feeding it. Decode and feed every other token,
including token 64. Record generated IDs and exact bytes, stop reason, final
position, independently parsed fields and correctness. Final position must be
4096 plus the number of generated non-EOS tokens; thus capacity 4160 suffices.
A complete valid object at the 64-token cap may pass; incomplete JSON may not.

## Frozen raw-JSON scorer and decision

Decode all generated bytes as strict UTF-8. Strip leading JSON whitespace only
(space, tab, CR, LF); the first remaining character must be `{`. Decode the first
JSON value. It must be an object with string `code` and `record`; reject missing,
non-string or duplicate required fields. Extra fields are allowed, as in v1;
they do not affect the answer. After the first value, only JSON whitespace is
allowed. Reject markers, markdown, leading prose, trailing commentary, additional
JSON values, non-JSON whitespace and malformed/nonfinite JSON. Do not extract an
object from prose, add a marker or repair the generation. Match required values
exactly to the frozen answer. This policy has no bitwise or KL criterion.

An A parse failure makes that case INCONCLUSIVE_INVALID_FIXTURE, never PASS.
When A parses, incorrect/unparseable B is FAIL even if parsed A is wrong. A
parsed-but-wrong answer does not excuse a wrong B; a correct B on such a case
passes, matching v1's validity convention. Report A correctness independently.
Per artifact, any valid-case FAIL dominates an inconclusive other case; otherwise
any inconclusive case makes the artifact INCONCLUSIVE; only two PASS cases make
the v2 retrieval follow-up PASS. Never pool artifacts or substitute test-exit
success for a quality verdict. Invalid bindings/order/admission/reset or A runtime
failure is INVALID_ACQUISITION; B runtime/nonfinite failure is SEMANTIC_FAIL.
Incomplete acquisitions cannot pass. No automatic model/schedule promotion.

A v2 PASS applies only to these two controlled raw-JSON retrieval cases at 4096.
It is not broad chat qualification and does not revise v1's frozen conclusion.
Owner review of prior NLL plus v2 evidence and a clean ordinary-call performance
repeat remain separate requirements before any production decision.

## Source lineage

V2 is a child of frontier_quality solely to reuse ordinary prefill/reset,
admission, geometry, and error-reporting helpers. The only v1 harness edit is
its new child-module declaration. v1-frontier_quality.rs.txt preserves its
exact source before that declaration, with hash in v1-bindings.json. Future
builds therefore have a different v1 harness source hash; historical raw source
bindings remain untouched. V1 protocol, fixtures, scorer and result files are
unchanged. This declaration does not amend the v1 quality policy.
