## Order And Decision Rules

1. Measure the current cost breakdown and worker-local hardware anchors first.
   Independently finish the small serving/CLI contract repairs; they do not need
   a roofline study or an arithmetic rewrite.
2. Attribute the retained slow suffix with fixed inputs, explicit seeds, cache
   source, absolute positions, capacity and checkpoint cuts. Report whether the
   reconstructed execution actually matches the historical shape.
3. Compare both retained artifacts with matching pp/tg shapes and a bounded
   quality probe before artifact-specific tuning or choosing a default.
4. Rank operator changes by recoverable milliseconds and end-to-end benefit,
   not a fixed guessed ordering or percent of theoretical peak alone.
5. Require an observed dispatch census for each optimization witness: resolved
   pipeline, shape, dtype, grid/tile and fallback. A shared matrix interface is
   not evidence of an MMA dispatch.

For each stage, report wall/GPU time and share, nominal arithmetic, logical
traffic and the applicable device anchor. `max(FLOPs / compute, bytes /
bandwidth)` is an optimistic work bound, not an exact runtime prediction.
Separate useful FLOPs from padded work and logical payload from measured DRAM
traffic. Encoding, IO, allocation, irregular gathers and synchronization have
different ceilings; inclusive wait and GPU intervals must not be added together.
Do not label an M4 Max measurement, a Q4_K matrix rate or a scalar FMA probe as
the M5 Ultra peak for F32 attention or sparse MXFP4 experts.
