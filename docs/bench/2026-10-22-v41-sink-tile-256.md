## What changed

The attention sink tile ran one threadgroup per (16-head block, query
row) for 32 query rows at a time: 128 threadgroups per dispatch on an
80-core GPU, so nothing hid the dependent `ids -> latent row` gather
latency and the serial accumulator chain. The fixture
(`mma_sink_tile_dispatch_timing`, 640 keys, full sink = score + softmax
+ PV + normalize) measures the cost per query row against the tile
width:

| rows per tile | simdgroup-MMA sink | tensor-ops sink |
|---|---:|---:|
| 32 | 437 us = 13.7 us/row | 518 us = 16.2 us/row |
| 128 | 1,194 us = 9.3 us/row | 1,191 us = 9.3 us/row |
| 256 | 2,050 us = 8.0 us/row | 1,927 us = 7.5 us/row |
| 512 | 3,420 us = 6.7 us/row | 3,294 us = 6.4 us/row |

Two changes follow from it:

- `TILE` 32 -> 256 (`attention_gpu/query_batch.rs`): the score and
  attended slabs grow with it (42 + 34 MB at 256 rows for the released
  geometry, priced through the existing admission path), and the gathered
  value matrix of the non-MMA PV branch is no longer allocated for the
  released geometry, which never takes that branch (it would have been
  335 MB at 256 rows).
- `kernel_deepseek_v41_attention_score_tensor` / `pv_tensor`
  (`kernels/tensor/deepseek_v41_attention_tensor.metal`): the MMA tile's
  QK^T and PV as one `matmul2d` per 16-key block (16 x 16 x 512 and
  16 x 512 x 16), same buffers, same score slab protocol, same
  `softmax_rows` / `normalize_rows`; selected where the tensor tier is
  (`moe_grouped_tensor_selected`). The row helpers moved to
  `kernels/deepseek_v41_attention.h` so both libraries share them. At
  32-row tiles the tensor kernels are not faster (the gather dominates);
  at 256 rows they are 6% faster than the MMA pair.

Numerics: half-staged Q/K/V and F32 sums as the MMA tile; the tensor
kernels differ from it only in reduction order (`tensor_sink_tile_matches_mma_sink`:
scores and outputs within 2e-3 relative of the MMA tile, half tolerance
of the scalar sink, the same invalid-selection and finite guards). The
tile width changes no arithmetic: each query row's keys, scores and
softmax are its own.

## Limits

- The tile width is a host constant; 512-row tiles measure another 16%
  per row in the fixture (slabs 84 + 67 MB) and are the obvious follow-up
  ABBA, not taken here.
- The sink tile still gathers each key row once for QK^T and once for PV
  and once per 16-head block (four blocks): a fused score+softmax+PV
  kernel over all heads of a row would read each key once. Open.
- M4 keeps the simdgroup-MMA kernels and gains only the tile width.
