# V4.1 prefill: 512-row sink tiles, +17-18%

Candidate `perf/v41-sink-tile` on main `d382a7d7` (after 4K fused
selection). The same-binary ABCCBA ran on `3e63384c` with
`QWEN_V41_SINK_TILE` selecting each arm; `580b6aa0` only changes the
default width to 512 and the test expectations, with no arithmetic change.
The post-landing split and census were taken at `580b6aa0`. M5 Ultra
80-core, macOS 27.0.1, Unsloth DeepSeek-V4.1-Flash-1017 UD-Q2_K_XL and
UD-IQ3_XXS, production lease, `qwen-bench suite --pp 2048,4096 --runs 2
--seed 1`. Same binary; the tile width is the only difference
(32 / 256 / 512 / 512 / 256 / 32 per artifact). Raw:
`metagross:~/qwen-runs/2026-10-22-sink-tile/abba/`.

## What changed

At 64 heads a 32-row tile dispatches `heads/16 * 32 = 128` threadgroups per
sink dispatch against 80 cores, and every threadgroup pays the dependent
`ids -> latent row` gather before its MMA tiles can issue. The tile is now
512 rows by default (`512 * 4 = 2,048` threadgroups). The arithmetic per
query row is unchanged on the released MMA geometry: each row still owns
its keys, scores, softmax and output, and layers/rows are processed in the
same order. Fallback (non-MMA) geometries keep the gathered-value-matrix
branch; a wider batch can change which grouped PV kernel that branch
selects, so the identity claim is scoped to the released geometry.

The MMA geometry never takes the gathered-value-matrix PV branch. That
matrix is now omitted from admission there instead of scaling with the
tile: at 512 rows it would have added about 755 MB per workspace. Net of
that removal, 512 rows admits about 100 MB more scratch than the original
32-row configuration; admission refuses a workspace that does not fit
rather than shrinking the tile.

The in-tree fixture shows the occupancy effect per query row (640 keys,
full sink; `QWEN_V41_SINK_TIMING=1`):

| rows per dispatch | full MMA sink | per row |
|---:|---:|---:|
| 32 | 549 us | 17.2 us |
| 64 | 744 us | 11.6 us |
| 128 | 1,193 us | 9.3 us |
| 256 | 2,046 us | 8.0 us |
| 512 | 3,425 us | 6.7 us |

The fixture is attribution only; the bench below is the acceptance number.
Its ragged start moves with `n` (average visible keys fall from about 631
at 32 rows to 511 at 512), so the per-row column mixes occupancy with less
work per row. It does not by itself prove the throughput gain.

## Throughput

Means of four samples (2 runs x 2 arms) per artifact and shape.

| artifact | shape | 32 rows | 256 rows | 512 rows | 512 vs 32 | 512 vs 256 |
|---|---|---:|---:|---:|---:|---:|
| IQ3_XXS | pp2048 | 644.8 | 743.4 | **756.9** | **+17.4%** | +1.8% |
| IQ3_XXS | pp4096 | 615.5 | 713.9 | **727.1** | **+18.1%** | +1.9% |
| Q2_K_XL | pp2048 | 652.7 | 753.2 | **767.9** | **+17.6%** | +2.0% |
| Q2_K_XL | pp4096 | 623.4 | 722.9 | **736.1** | **+18.1%** | +1.8% |

Sample ranges: IQ3 512 pp2048 753.8-760.3, pp4096 724.8-729.2; Q2 512
pp2048 767.4-769.5, pp4096 731.4-739.1. The 256-row arm captured most of
the gain; 512 adds another 1.8-2.0% and is the new default.

## Correctness

- 45 V4.1 tests pass (31 attention, 14 prefill), including a 513-row case
  that crosses the tile boundary and the threshold census pinned to the
  production width.
- Same-build held-text witness, IQ3, 384 targets: 32, 256 and 512 rows
  produce identical logits (concatenated SHA-256
  `b90633d032d9eb12616ff970ea47b16a0730c4a267bb02b2c24b36ef60d853cd`),
  identical mean NLL 2.146367194 and top-1 0.5677. The 512-row build
  rerun reproduces the same values.
- The frozen witness uses a 512-token prefix, so it exercises one tile.
  A separate diagnostic probe (the same six documents with the 512-token
  prefix repeated four times to 2048 tokens; the helper's prefix constant
  patched only for the probe) gives identical logits at 32 and 512 rows
  (concatenated SHA-256
  `5126c2fa6b193f933ba26f6bfdae1d010aa1d798260bda1d95c16ec2fb3a0a43`).
  This covers one full 2048-token chunk and four tiles; PP4096 is two such
  chunks and is not separately hashed.

## Limits

- One artifact pair, one M5 Ultra. The 512-row choice is measured against
  32 and 256 only. A follow-up IQ3 A/B/B/A probe of 1024 rows is flat
  (pp2048 759.6 vs 757.6, pp4096 727.1 vs 726.6), so 512 stays the knee and
  1024 adds scratch without throughput. The 512-vs-256 margin is 1.8-2.0%;
  it agrees across both artifacts and both ABCCBA directions, but no
  separate thermal cycle was run for that small delta.
- The 2048-token identity probe covers one prefill chunk. PP4096 uses two
  chunks; it is measured for throughput but not separately hashed.
- Sink scratch grows linearly with the tile: at 512 rows the score slab is
  84 MB and the attended slab 67 MB per workspace. Admission prices them;
  the removed value matrix would have been larger still.
- Prefill only. The tile does not run in decode. Decode was rechecked on
  the landed binary: tg32 Q2 43.1, IQ3 40.5, inside the previous 43 / 41
  spread.
