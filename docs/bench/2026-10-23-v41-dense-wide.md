# V4.1 prefill: 64-slot dense tensor tile, +3.4-3.6%

Candidate `perf/v41-dense-wide` (`1a5a6c9a`) on main `84c465db` (after
the GLM tensor merge). M5 Ultra 80-core, macOS 27.0.1, Unsloth
DeepSeek-V4.1-Flash-1017 UD-Q2_K_XL and UD-IQ3_XXS, production lease,
`qwen-bench suite --pp 2048,4096 --runs 2 --seed 1`. Same binary; the
tile width is selected with `QWEN_V41_DENSE_NARROW=1` (narrow) versus the
default wide. ABCCBA per artifact. Raw:
`metagross:~/qwen-runs/2026-10-23-dense-wide/`.

## What changed

The dense Q8_0 tensor tile staged one 64-row weight slab for a 32-slot
activation group and re-dequantized the same weights for every 32 query
rows. The wide form stages the same weight slab for **two** 32-slot
groups, so the weight dequant/staging work per output row halves. The
output staging grows from `[32][64]` to `[64][64]` F32 (8 -> 16 KiB
threadgroup memory); the K-step order and per-output arithmetic are
unchanged.

Selected only for Q8_0 (the V4.1 attention/output/shared-expert dtype)
and from 128 query rows. Below that the padded second slot group loses
(measured 64/96 rows: 12-14% slower); `QWEN_V41_DENSE_NARROW=1` forces
the 32-slot tile for same-binary measurement.

## Correctness

- The wide and explicit 32-slot tiles are **bitwise equal** (F32 `to_bits`)
  at 320x130 and 321x97, covering a partial second slot group, a 2-slot
  final tile, and a 1-row output tail; both match the CPU reference.
- Invalid/padded activation rows are staged as zeros, so the tail MMA
  never reads uninitialized threadgroup memory.
- IQ3 held-text witness, 384 targets: narrow and wide produce identical
  logits (concatenated SHA-256
  `b90633d032d9eb12616ff970ea47b16a0730c4a267bb02b2c24b36ef60d853cd`)
  and the same NLL 2.146367194 / top-1 0.5677.
- 69 tests pass: 31 attention, 14 prefill, 23 dense (including the wide
  equality and batch timing cases).

## Limits

- One M5 Ultra, one artifact pair. The wide tile is Q8_0-only; other
  dense dtypes and <128-row calls keep the 32-slot form.
- The 16 KiB output tile halves the resident threadgroup count relative
  to the 8 KiB form; the measured gains already include that occupancy
  cost. Decode and other families do not use this tile.
- A 64-slot x 128-row combined probe (`perf/v41-dense-combined`) is
  bitwise correct but 22-57% slower per dispatch: the 32 KiB output
  staging and 64-float accumulator lose occupancy. 64x64 is the knee;
  the combined branch is retained as negative evidence.
- The full-model ABBA ran on `60477316`; the final `1a5a6c9a` only moves
  the selector threshold to 128 rows (2048-row arms are identical).
