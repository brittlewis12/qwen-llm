# V4.1 All-Head 64x32x128 Tensor Attention Tile

2026-10-26. Source: `e0230244` (on `f191c303`, `ddcec6b6`). Artifact: GSQ-RCO
IQ2_XS, 40 layers, 4,096-row chunks, M5 Ultra. Raw:
`metagross:~/qwen-runs/2026-10-26-v41-attn64/`.

## Decision

Promote. The score and PV tiles now run one threadgroup per query row with all
64 heads: Q 16 KiB, a 32-key K panel 8 KiB, and the 32x64 score block 8 KiB at
the 32 KiB threadgroup limit, with four 128-wide latent chunks accumulating
into one cooperative tensor. Same-binary 8K with a 180 s inter-arm cooldown:
new 918.88/918.43 and 918.03/916.91 tok/s, control 900.63/899.68 and
900.58/899.76, **+1.99%**, every sample stable. The 2K greedy endpoint is
byte-identical (45 bytes). `QWEN_V41_SINK_TENSOR64=0` restores the 16-head
blocks.

## Why

The 16-head tensor tile runs four threadgroups per query row and gathers each
key row once per 16-head block, so the selected compressed keys are read four
times. The 64-head form reads them once and runs a 4x larger tensor M. The
profiled `prefill_attention_tiles` span falls from 4,051.0 to 3,700.7 ms (the
same two-run stage protocol), **-8.6%**. The wall gain is smaller (+1.99%)
because the per-row selected gather, the four Q reloads per key panel, and the
retained F32 score slab dominate the tile; the tensor arithmetic is no longer
the limiting term. The remaining attention lanes are the span-wide window band,
the selected-row gather format, and the dense Q5_K/Q8_0 projections.

## Correctness

- The raw tensor witness (`tensor64_sink_tile_matches_tensor32_sink`) compares
  the 64-head score and PV with the existing tensor32 tile over K=256/512/640,
  ragged and ordered visibility, and several query widths.
- The first build dispatched `threadgroup_position_in_grid` as a scalar while
  the grid was (width 1, height n), so every threadgroup processed row 0; the
  2K endpoint caught it. The fixed form uses `uint2 group` / `group.y`.
- The 2K greedy endpoint is byte-identical to the 16-head path
  (sha256 `b47cc0f104b62d4c7c30bcd68fd8e67613e287dc4ad8c310ef10cbadea9c4380`).

## Campaign

Campaign lease, 120 s pre-campaign cooldown, discarded stage-profiled warm-up,
then N C C N with 2 runs per arm and **180 s between arms**:

| arm | samples (tok/s) | mean |
| --- | --- | ---: |
| N | 918.88, 918.43 | 918.65 |
| C | 900.63, 899.68 | 900.15 |
| C | 900.58, 899.76 | 900.17 |
| N | 918.03, 916.91 | 917.47 |

The earlier publication campaign showed a 9% thermal drift when arms ran
back-to-back (last control 794.3). The 180 s inter-arm cooldown removes that:
all four arms are stable and the reversed pair agrees. Single-call and
sustained rates coincide here because each arm is cooled.

## Limits

One artifact and one host session. The stage span is not a native wall; compare
spans within the same protocol. The 64-head form requires 64 heads and a
512-wide latent with the Metal 4 tensor tier; other geometry keeps score32/PV
or the MMA path. The publication and tile are independent toggles; this
campaign isolates the tile (`COMPRESS_ROWS` is on in both arms). The remaining
attention budget is dominated by the selected-row gather and the score slab,
not the tensor matmul.
