# V4.1 Dedicated Q5_K Dense Tensor Tile

2026-10-26. Source: `e331ee5b` (on `2b2706a4`, `e7207226`, `90d0d542`).
Artifact: GSQ-RCO IQ2_XS, 40 layers, 4,096-row chunks, M5 Ultra. Raw:
`metagross:~/qwen-runs/2026-10-26-v41-q5k-tensor/` and
`metagross:~/qwen-runs/2026-10-26-v41-q5k-matmat/`.

## Decision

Promote. Q5_K dense rows now use the dedicated 64-query x 64-output x 32-K
tensor GEMM by default instead of the generic dense Q5_K narrow tile. The
same-binary 8K campaign with 180 s inter-arm cooldowns, N C C N x2: dedicated
1,046.33/1,045.43 and 1,053.20/1,052.48 tok/s, generic 1,022.70/1,023.20 and
1,024.35/1,023.30, **+2.54%**, every sample stable. The 2K greedy endpoint is
byte-identical. `QWEN_V41_Q5K_MATMAT=0` restores the generic dense path;
`QWEN_MATMAT_Q5_K_TENSOR=0` further selects the simdgroup Q5_K form.

## Why

V4.1 prefill already used a Metal 4 dense tensor route for Q5_K, but only its
32-query narrow form; the 64-slot wide form was instantiated for Q8_0 only.
The dedicated kernel stages 64 queries and 64 outputs with a 32-wide K step:
the activation tile (4 KiB) and the Q5_K weight tile (4 KiB) fit in 8 KiB of
threadgroup memory, the 64x64 F32 accumulator is in the cooperative tensor,
and each thread dequantizes one 16-element Q5_K subtile. The prefill route now
selects it for output_b, q_b, output_a and the shared expert.

Profiled two-run sums: `finish_post` 2,214.0 -> 2,081.1 ms (-6.0%),
`prepare` 1,317.4 -> 1,114.2 ms (-15.4%), `ffn` 6,227.2 -> 6,156.8 ms
(-1.1%). Attention tiles, serial and HC are unchanged. The finish/FFN parts
are now at the Q5_K dequant/tile limit; the remaining large term is the routed
IQ2_XXS expert GEMM.

## Correctness

- The 2K greedy endpoint is byte-identical between the dedicated tile and the
  generic dense path (45 bytes, sha256
  `b47cc0f104b62d4c7c30bcd68fd8e67613e287dc4ad8c310ef10cbadea9c4380`).
- The Q5_K dequant is copied from `kernels/mat_mat_q5_k.metal`; the dedicated
  kernel stages the same half operands and F32 accumulator. A raw
  `mat_mat_q5_k` tensor witness against the simdgroup form is still owed; the
  2K endpoint is the integration gate used here.
- The generic dense path and the simdgroup n16/n64 forms remain available, so
  a numerical or performance regression can be isolated per call.

## Limits

One artifact and one host session. The route needs n_query and n_out multiples
of 64 and n_in a multiple of 256; other shapes keep the generic dense or
simdgroup path. The endpoint is 12 greedy tokens, not a quality sweep. The
dedicated kernel lives in the generic metal dispatch, so Q5_K shapes in other
models with the tensor tier can use it; those models still need their own
endpoint/quality checks. The fused tensor-PV normalization is a separate
default-off candidate, not part of this landing.
