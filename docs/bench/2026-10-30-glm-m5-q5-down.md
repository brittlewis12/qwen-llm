# Default-Off GLM Q5_K Expert Down Experiment

## Scope

Prepared against `5bf7e4e5` in `perf/glm-m5-q5-down`. The corrected user-artifact
named header audit v3 reports 43 serialized expert-down banks: 40 Q5_K and 3 Q6_K.
The 42 executed routed blocks (3 through 44) have 39 Q5_K down banks and Q6_K
down at exactly blocks 11, 12, and 44. Main block 11 has Q5_K gate AND up;
the other 41 routed blocks have Q4_K gate/up (82 Q4_K plus 2 Q5_K banks,
42 pairs), all with GGUF shape [4096, 2048, 288]. Unused MTP block 45 stores
one Q5_K down and two Q4_K gate/up banks. Thus the aggregate 84 Q4_K gate/up
banks do not imply uniform main-model gate/up, and the aggregate 42 Q5_K
matrices are not 42 eligible down calls: this experiment
affects 39 down calls per eligible full main-model chunk, preserving the three
Q6_K incumbent down calls. All 39 Q5-down candidate blocks retain Q4_K gate/up;
block 11's Q5_K pair is excluded because its down is Q6_K.
The existing IQ3_S-only tensor-down selector covers
none of those Q5_K banks; its prior model results do not qualify this artifact.

Named Q8_0 MLA banks are pinned separately: main blocks 3, 7, ..., 43 have
`attn_k_b` [256, 512, 64] and `attn_v_b` [512, 256, 64], 11 executed pairs
(22 banks). MTP block 45 contributes the twelfth serialized pair, not another
executed pair.

`QWEN_GLM53_TENSOR_Q5_DOWN=1` opts into a separate `Q5KTensor` policy. It is
default OFF, with a nestable, panic-safe thread-local test override for A/B.
That override is `tensor_q5_down::Scope`; the existing IQ3_S-only
`tensor_down::Scope` does not control this experiment.
Production selection requires Fast lineage, Half precision, resolved Fast
expert mode, native Q5_K, K=2048/M=4096/E=288/top-8, and exactly 1024 or 2048
actual committed rows (not backing capacity). Other widths/shapes/modes keep
the incumbent; existing IQ3_S policy and the separate Q8 work are unchanged.

## Implementation Contract

- Reuse `kernel_moe_down_q5_K_f32_grouped_slots_tensor` through the existing
  prepared shared adapter, bounded to IQ3_S/Q5_K; no shader, buffer, expanded
  weight bank, or F16 activation staging is added.
- Q5_K row bytes are K/256*176. Overflow, device, physical extents, alignment,
  writability, aliasing, explicit dtype/policy agreement and pipeline capacity
  are checked before bucketing/gate-up writes. Missing eligible pipelines or
  invalid bindings are errors. Unsupported capacity declines before mutation;
  the caller then uses the whole incumbent down dispatch.
- Capacity requires SIMD width 32, support for 128 threads and static plus
  8192 dynamic threadgroup bytes within the device limit.
- The shared M5 tensor-tier/global `QWEN_EXPERT_TENSOR_TILE` rollback guard is
  unchanged and precedes pipeline lookup. M4 and global OFF retain the generic
  composition. No V4 path or admission exception changes.
- F32 activation storage still becomes Half operands inside the tile, with
  F32 accumulation. Tensor versus simdgroup-MMA reduction order changes; this
  is not a bitwise-equivalence claim. Q4_K gate/up, bucketing, unweighted down
  inputs and post-down routing-weight reduction are unchanged.


The four test filters pass 2+3+3+2 = 10 CPU tests. Builds retain unrelated
existing Rust warnings and the optional, unsupported Metal 4.1 compiler-probe
warning; the Metal 4.0 tier compiles. New CPU contracts:

- `glm5_next_metal::tensor_q5_down::tests::cpu_q5_down_policy_bounds_arithmetic_dtype_geometry_topk_and_committed_rows`
- `glm5_next_metal::tensor_q5_down::tests::cpu_q5_down_default_off_scope_is_nested_thread_local_and_unwind_safe`
- `metal::expert_tensor_down::tests::cpu_tensor_q5_down_native_bytes_pipeline_and_bounded_dtype_contract`

One new ignored GPU witness:
`glm5_next_metal::tensor_down::tests::m5_q5_down_q4_gate_up_composed_f64_and_preflight_contract`.
It reuses the existing native fixture, sparse routing/bucket boundaries,
guarded buffers, F64 full/Half-operand down oracles and weighted-output checks.
It also samples composed down against F64 using the actual gate/up output,
compares complete incumbent/candidate dispatches, and checks missing-pipeline,
bad-binding, policy-mismatch and capacity-preflight behavior before mutation.

The private witness keeps production K/M/top-8 and R1024/R2048, but uses E32;
CPU selection explicitly rejects this E32 geometry in production. Its existing
full native-storage ledger includes both independent Q4_K banks, Q5_K down,
all scratch/guards/priced buffer upper bounds, and 6x CPU headroom plus 32 MiB.
It asserts the priced GPU total is at most 1 GiB and drains each width's
autorelease pool before the next. This test-only budget is not a new runtime
admission cap. No expanded weights or bypasses are used.

No GPU test, inference, timing, model A/B or M4 run is performed in this CPU
preparation unit. Parent qualification must run the ignored witness under its
normal actual-M5/validation/production-lease requirements, then whole-model
same-binary A/B on the audited artifact with ordinary wall/TTFT, quality and
continuation/tool checks before any promotion. No speedup is claimed.

Parent-owned integration inventory needs: document the new default-off flag
and its cached per-process semantics, the three CPU contracts, the ignored
GPU witness and the arithmetic/model-qualification boundary. Any existing
down-only model A/B harness must control the new Q5 scope explicitly rather
than relabeling the IQ3_S scope. Central PERFLOG,
ENV and acceptance inventory files are intentionally not edited here.
