## What The Predicate Means

For every head and key column, the prerequisite requires both a magnitude-nonzero
coefficient and bit variation across value rows. Failure can mean an all-zero/
signed-zero-only column OR a bit-constant nonzero column. The shared error label
does not identify the failed block, head, key or conjunct.

The checker uses `((head*128 + value)*128 + key)*4`, matching the ordinary kernel,
state specification and CPU oracle. Independent source review finds no indexing
or sparse-frontier bug. The old first-block checker has the same predicates; the
new gate extends them to all34 KDA states.

The failing state's4MiB payload passes `finite()` before these predicates. That
does not establish every later state's or the returned endpoint's finiteness:
those checks were not all reached, and no state payload is retained.

This richness condition is a deliberate witness-coverage prerequisite, not a
general KDA semantic invariant. An initially zero state column stays zero if its
prepared key coordinate stays zero. Valid constant columns are not forbidden.
Conversely, low rank alone does not imply zero columns. These mathematical facts
do NOT establish why this actual state refuses; preparation/write defects or
legitimate input structure cannot be distinguished from the current evidence.

Only a separately reviewed baseline-only inventory is being prepared to localize
and classify the refusal using bounded counts/hashes. It must preserve this
failed qualification, keep the same prefix, and run no candidate or acceptance
retry. Inventory completion would not qualify the candidate or justify changing
the original guard. State/input support needs further evidence if its cause
remains unresolved.
