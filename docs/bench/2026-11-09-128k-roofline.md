## Accounting at 128K

Use the unchanged executed tensor roles and actual artifact types audited in
the November 6 GLM/Flash-Next roofline entries. GLM includes its 8/288 routed
banks, fixed F32 KDA state, selected F16 latent rows and pooled index keys;
Flash-Next includes 10/512 banks, widened native weights, F32 GDN state,
selected F16 QSA K/V and pooled index keys. Sparse selection bounds attention
payload at both 32K and 128K. Only pooled-index scan traffic grows with depth.

The audited tg64-at-32K bases are **10.573347 GB/token GLM** and
**5.622110 GB/token FN**. Each pooled key is 128 F16 elements, published every
four positions: 11 GLM attention layers give **704 bytes/depth-position**;
12 FN layers give **768**. TG256's mean position is 96 later than TG64's:

```text
GLM bytes = 10.573347e9 + (131072 - 32768 + 96) * 704 = 10.6426206e9
FN  bytes =  5.622110e9 + (131072 - 32768 + 96) * 768 =  5.6976812e9
decode roof fraction = tok/s * bytes/token / 1175.47e9
```

The useful pp512-at-32K bases are **35.909171 GFLOP/row GLM** and
**12.761350 GFLOP/row FN**, including the once-per-call endpoint head. At
the same 512-row shape, learned projections and selected attention work remain
fixed. Index score products add `2 * query_heads * 128 * layers / 4` FLOPs per
depth-position/query: **22528 GLM** (32 index heads) and **3072 FN** (four).

```text
GLM FLOPs = 35.909171e9 + (131072 - 32768) * 22528 = 38.123763512e9
FN  FLOPs = 12.761350e9 + (131072 - 32768) *  3072 = 13.063339888e9
append roof fraction = tok/s * FLOPs/row / 131.676e12
```

Published base accounting is rounded; percentages are reported to one decimal.
Ideal useful-compute-only pp512 times would be **148 ms GLM / 51 ms FN**.
The measured 761/373 ms include the other work above. The screen supports
targeting native decode and small-row append kernels; it does not establish
which leaf kernel owns the gap. For concurrent agents, FN batching remains
the larger immediate lever; GLM already benefits from batching.

## Reproduce

One fresh process and one untimed 131072-token prefix per cell. Ordinary
known-input scalar decode, full endpoint-logit copies and GLM route checks;
ordinary production packed append with endpoint logits. No extra row warmup,
sampling or instrumentation. Prefix fills warm the model and are outside the
row timer. Whole commands, including loads and prefix fills, took **149.7 /
73.4 / 134.5 / 71.6 s** for GLM tg / FN tg / GLM pp / FN pp respectively.

```sh
# Build qwen-bench at the engine commit above under the build lock.
# Then, once per cell, under only the Metal lease (no build lock):
QWEN_METAL_LEASE_WAIT=1 nice -n 10 scripts/bench/with-metal-lease \
  --task steady-roof-glm-tg --for 5m -- \
  target/release/qwen-bench suite -m MODEL.gguf --depth 131072 \
  --runs 1 --no-warmup --seed 1 -o json --tg 256
# Separate fresh process for the append: replace --tg 256 with --pp 512.
```

Actual model paths and argv are in the CSV. A controller cools 25 seconds,
requires three zero thermal readings three seconds apart, monitors every
second and stops on nonzero pressure or deadline. All four cells return zero,
have matching clean build/runtime identities and all thermal samples **0**.
Only one model is resident. Compact row/thermal JSON is under
`$HOME/qwen-runs/2026-11-08-realistic-steady/` on both hosts. Regenerable build
scratch and bundle were removed at **2026-11-09T05:32:36Z**; no owned server,
benchmark or tunnel remains.
