# V4.1 packed-reference index scorer: closed

**Disposition: no-go on the standalone scorer.** Its pack and dequant stages
match the scalar contract bitwise, and the SIMDgroup score matches the scalar
packed-score oracle on the captured real inputs. The isolated score stage is
2–2.9× slower than the current F32 MMA, and the reference-precision scores
change many of the actual top-512 selections. No runtime path or default was
changed.

## Contract and implementation

The M5 probe used the model's 32 heads × 128 dimensions, four 32-value E2M1
blocks per row, UE8M0 per block, separate value/scale planes totaling 68 bytes
per row, and F32 output scores. Query and key packing used the existing
contract pack kernel and oracle. The scorer stages decoded E2M1 units into
SIMDgroup half tiles, applies the exact power-of-two block scales after each
32-value MMA, then performs the 32-head weighted sum. Its reduction order is
free to differ from the scalar oracle.

M5 bitwise pack witness: **32,768 query rows and 131,072 key rows** matched the
oracle's E2M1 bytes and UE8M0 scales. The separate F32 dequant witness matched
the scalar decoder bitwise for **4,194,304 query values and 16,777,216 key
values**. In the three-query × three-key score witness, maximum absolute and
relative score error were both zero.

On the real captured inputs at all eight index layers, the SIMDgroup output
also matched the scalar packed-score result exactly: max absolute error `0`,
max relative error `0`. The implementation follows our local scalar contract
in `deepseek_v4_oracle.rs` and the existing diagnostic pack semantics in
`deepseek_v4_metal/indexer.rs`; no MLX or other external implementation code
was copied.

## Isolated score gate

The M5 test-profile binary compared the current `index_heads_rows_mma` F32
kernel with the standalone E2M1/UE8M0 scorer. It used two warmups per arm and
three interleaved A/B pairs per cell, with both arms in the same binary and
`nice -n 0`. The timings below are median GPU milliseconds; speed is
`F32-MMA / packed-reference`.

| Key rows | Query rows | F32 MMA ms | Packed reference ms | Speed |
|---:|---:|---:|---:|---:|
| 80,000 | 1 | 0.0644 | 0.1216 | 0.529× |
| 80,000 | 2 | 0.0968 | 0.2327 | 0.416× |
| 80,000 | 3 | 0.1338 | 0.3448 | 0.388× |
| 80,000 | 256 | 6.0134 | 17.3754 | 0.346× |
| 80,000 | 1,024 | 23.9371 | 69.2685 | 0.346× |
| 128,000 | 1 | 0.0590 | 0.1154 | 0.511× |
| 128,000 | 2 | 0.0893 | 0.2246 | 0.398× |
| 128,000 | 3 | 0.1287 | 0.3340 | 0.385× |
| 128,000 | 256 | 9.6263 | 27.7879 | 0.346× |
| 128,000 | 1,024 | 38.4710 | 111.0310 | 0.347× |

The ≥1.25× stage gate failed in every cell. Smaller key traffic did not repay
the packed path's repeated nibble extraction, shared-half staging, barriers,
block scale epilogues, and narrower tile schedule. This is the same active-tile
cost class seen in the earlier IQ expert probes: reducing bytes alone did not
compensate for decode and staging work.

## Real-input selection screen

The test loaded production file A, `DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XS`,
filled an 80K prefix, then appended 256 tokens. It captured the final query,
head weights, and key prefix at position `80,255` from each of V4.1's eight
index layers. For reproducibility the prompt used the seven-token sequence
`[0, 5, 223, 939, 23, 695, 22]` repeated to the requested lengths. This is a
real model execution, but the token pattern is synthetic rather than a replay
from agent traffic. Its repeated seven-token pattern creates many key near-ties
(boundary margins around `1e-5`), so the 6.6–90.0% overlap range likely
exaggerates selection drift relative to real text.

At each layer, the table compares the actual current F32 selection with the
packed-reference selection. Margins are score-at-rank-512 minus score-at-rank
513. These are measurements, not a newly invented quality threshold.

| Layer | Ratio | Visible keys | Top-512 overlap | Current margin | FP4 margin | Head-wise mean / minimum overlap |
|---:|---:|---:|---:|---:|---:|---:|
| 2 | 2 | 40,128 | 387 / 512 (75.6%) | 6.366e-5 | 2.468e-5 | 85.3% / 50.2% (head 26) |
| 8 | 2 | 40,128 | 461 / 512 (90.0%) | 4.232e-6 | 1.872e-5 | 92.1% / 38.5% (head 15) |
| 14 | 2 | 40,128 | 453 / 512 (88.5%) | 2.408e-5 | 8.097e-5 | 89.4% / 45.9% (head 8) |
| 20 | 1 | 80,256 | 319 / 512 (62.3%) | 1.645e-5 | 1.073e-6 | 72.1% / 1.0% (head 6) |
| 24 | 1 | 80,256 | 34 / 512 (6.6%) | 1.323e-5 | 9.060e-6 | 64.9% / 0.2% (head 16) |
| 28 | 1 | 80,256 | 288 / 512 (56.3%) | 1.931e-5 | 3.743e-5 | 54.9% / 0.2% (head 19) |
| 32 | 1 | 80,256 | 160 / 512 (31.3%) | 2.193e-5 | 8.821e-6 | 61.2% / 0.0% (head 17) |

The worst aggregate case is layer 24 at 34/512 overlap. Across the eight
layers, aggregate current margins ranged `4.232e-6`–`6.366e-5` (median
`1.788e-5`); packed-reference margins ranged `1.073e-6`–`8.097e-5` (median
`1.401e-5`). Maximum absolute score delta from current F32 was `0.294984`.
The largest relative delta was `8.03e3` under `abs(delta)/max(abs(current),
1e-6)`, driven by near-zero scores.

The head-wise column is a counterfactual diagnostic: V4.1 selects after
combining all 32 heads, and individual-head rankings are not used by the
runtime. FP4 per-head boundary margins were zero at the median because ReLU
produced many tied zero scores.

This precision path is more faithful to the model's packed reference, but the
screen shows large selection changes against today's higher-precision path.
The stage is rejected on speed regardless; any different fast implementation
would need a new score/selection quality screen and then NI before integration.

## Half-precision tensor MMA speed bound

The follow-up used the production 32-head ×128 index-score geometry on M5 Ultra.
It compared the current F32 simdgroup-MMA kernel with F16 and native BF16
simdgroup-MMA variants, both retaining F32 weights and accumulation. The
deterministic synthetic F32 Q/K buffers were converted to each 16-bit format
before timing; input conversion, FP4 pack/dequant, and model execution were
outside the isolated score span. Two warmups per arm and three rotated
interleaved samples per arm were used. The accepted process ran foreground at
nice 0; thermal pressure was 0 throughout the 60-second settle. Host load
average was `19.68 / 19.47 / 22.16`; no model was loaded.

Times are median GPU milliseconds; speedup is F32 / candidate.

| Key rows | Query rows | F32 | F16 | F16 speedup | BF16 | BF16 speedup |
|---:|---:|---:|---:|---:|---:|---:|
| 80,000 | 1 | 0.08483 | 0.08246 | 1.029× | 0.08300 | 1.022× |
| 80,000 | 2 | 0.14417 | 0.13800 | 1.045× | 0.13717 | 1.051× |
| 80,000 | 3 | 0.20550 | 0.19838 | 1.036× | 0.19921 | 1.032× |
| 80,000 | 256 | 6.02092 | 5.95588 | 1.011× | 5.95675 | 1.011× |
| 80,000 | 1,024 | 23.94825 | 23.75300 | 1.008× | 23.75804 | 1.008× |
| 128,000 | 1 | 0.07004 | 0.04833 | 1.449× | 0.04733 | 1.480× |
| 128,000 | 2 | 0.10708 | 0.08675 | 1.234× | 0.08917 | 1.201× |
| 128,000 | 3 | 0.14771 | 0.12558 | 1.176× | 0.12525 | 1.179× |
| 128,000 | 256 | 9.63383 | 9.52500 | 1.011× | 9.52704 | 1.011× |
| 128,000 | 1,024 | 38.34567 | 38.04438 | 1.008× | 38.04775 | 1.008× |

The required ≥1.25× gate fails at both 256 and 1,024 rows for both key depths
and both 16-bit formats. The one-row 128K speedup is not a prefill pass. The
256/1K score times barely change when Q/K element width is halved, indicating
that operand precision is not the dominant cost in this tile schedule. No
quality screen or runtime knob was added; the test-only kernels were reverted.

## Cache size and run record

At 128K, the four V4.1 owner banks retain 327,680 index-key rows per session
(three ratio-2 banks and one ratio-1 bank). F32 uses 160 MiB per session;
68-byte packed rows use 21.25 MiB. At three sessions that saves **416.25 MiB**
(436,469,760 bytes) in key payloads, excluding metadata and other state.

M5 run outputs are under `~/qwen-runs/2026-11-13-v41-fp4-indexer/`; the
selection test recorded no resident model before load, `nice=0` for its test
binary, a 1.15 s model load, 55.67 s prefix fill and 333.91 ms append. The
test-profile binary SHA-256 was
`40c0cb5be3ba6cbe45fa9300b48058020022d9624457af4903425e9d502fd8cb`.

The experiment did not modify `query_batch.rs` or runtime defaults. The
standalone kernel, test hook and probe tests are removed after this record;
the add/revert history remains on `perf/v41-fp4-indexer`.
